# 心愿空间迭代记录

这份记录只保留产品结构或体验方向发生明显变化的节点。字体、间距、图标尺寸等连续微调被合并进相邻里程碑，避免用大量无意义版本制造“迭代很多”的假象。

## v0.3 · 核心原型

目标是验证最朴素的使用场景：用户记录自己想要的东西，朋友进入群组后获得更准确的送礼参考。

- 支持“灵感”和“具体商品”两类心愿
- 支持群组创建、邀请码加入与分享范围
- 支持秘密认领和已购买状态
- 建立可选 Supabase 多账号数据结构

## v0.6 · 群组与生日信息架构

主页信息过多后，将成员和生日能力重新组织到群组与统一日历中。

- 增加群组成员空间
- 增加完整月历与下一位生日提醒
- 增加类别、类型、预算和优先级筛选
- 将群组详情和邀请码集中管理

## v0.9 · 个人心愿优先

重新回到产品的第一需求：用户首先是记录自己的心愿，其次才是查看朋友的心愿。

- 首页调整为“我的心愿”优先
- “我的心愿”与“群组心愿”形成清晰分区
- 增加心愿详情编辑闭环
- 恢复商品图片并改为更轻的平面列表
- 收紧说明文案，减少不必要的提示语

## v1.0 · 体验收口

在不改变核心交互逻辑的前提下，统一视觉层级与操作密度。

- 统一常规字重与字号层级
- 增加双向排序、加入时间与消息入口
- 统一筛选、状态切换和排序控件高度
- 修正头像、筛选弹层、空状态等细节
- 接入 GitHub Pages 自动部署

历史分支是根据开发过程保留下来的代码快照，演示身份与生日等信息均为虚构数据。
